How the shuffle should behave

  • Pick once per launch, not per view. The ground is one continuous surface across home, recording and document — if it re-rolled on a phase change, the morph we spent this whole conversation on would be pointless. One draw at launch, held for the process.
  • Never re-roll mid-session. A meeting that starts on one ground and finishes on another reads as a bug, and the warming is already using that channel to say something.
  • Avoid an immediate repeat. Store the last palette’s id and exclude it from the next draw. With a set of ten, a naive random repeats about one launch in ten, which is exactly often enough to read as broken.
  • Seedable for tests. The chooser takes a RandomNumberGenerator, so snapshots pin a palette and the invariant tests can walk all of them.
enum Ground {
  static func pick(excluding last: String?,
                   using rng: inout some RandomNumberGenerator) -> Palette {
    let pool = all.filter { $0.id != last }
    return pool.randomElement(using: &rng) ?? all[0]
  }
}

One thing to decide with it. A palette that changes per launch means the app has no fixed colour — which is either the charm of it or a problem, depending on whether you ever want someone to recognise Nota by its ground. The ember is unaffected either way; it is a signal, not a palette member, and no ground here may use it.
